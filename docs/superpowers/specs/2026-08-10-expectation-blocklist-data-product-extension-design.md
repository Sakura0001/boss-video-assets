# 求职期望黑名单扩展设计

## 目标

把主动打招呼前的求职期望硬编码黑名单从六项扩展为八项：`算法`、`通信`、`硬件`、`前端`、`unity`、`电气`、`数据`、`产品`。命中任一关键词的候选人不得打招呼，也不得发送后续三条固定消息。

## 已确认的匹配语义

- 继续只检查推荐页提供的 `candidate.expect`，不检查教育专业、个人优势或其他字段。
- 匹配前继续移除全部空白并转为小写，然后执行子串匹配。
- `数据` 是宽泛子串，因此“数据工程师”“大数据开发”“数据产品”等均被拦截。
- `产品` 是宽泛子串，因此“产品经理”“产品运营”“数据产品”等均被拦截。
- 空期望或未命中八项黑名单时，继续执行现有毕业年份、学历、学校、专业和去重门槛。
- 命中后只使用内部原因 `expectation_blocked`；不向候选人解释筛选原因，也不把完整求职期望写入本地状态或 Git。

## 方案选择

采用现有硬编码元组追加两个词的最小方案。未采用配置化加载，因为用户明确要求硬编码，且本次没有运行时调整需求；未采用只改 Python 的快速方案，因为那会让唯一业务来源、仓库镜像和执行逻辑不一致。

## 变更范围

1. 在 `scripts/greet_only.py` 的固定元组末尾追加 `数据`、`产品`，不改资格判断算法。
2. 先更新已安装的 `boss-zhaopin` 源 skill：资格门槛、主动打招呼说明、学校策略及契约测试均从六项改为八项。
3. 使用源 skill 的同步脚本覆盖仓库 `skills/boss-zhaopin/` 镜像，不独立维护镜像规则。
4. 不修改 Boss CLI 字段采集，不读取或保存额外候选人信息，不运行真实打招呼。

## 测试设计

- 先在顶层资格测试中增加“上海 数据工程师”和“上海 产品经理”，并把固定元组精确断言改为八项，确认旧实现会失败。
- 扩展流程级测试，放入分别命中 `数据`、`产品` 的候选人及一个正常候选人，确认命中者不会进入 greet、去重、事件、状态或三条消息发送。
- 先更新源 skill 契约测试为八项并确认旧文档会失败，再修改源文档使其通过。
- 同步后运行源 skill、仓库镜像、顶层 Python 测试、同步一致性检查和 `--validate-only`。

## 成功标准

- 期望中含 `数据` 或 `产品` 的候选人返回 `expectation_blocked`，不会触发任何真实发送动作。
- 八项黑名单的精确顺序由测试锁定，未命中候选人的其他资格门槛保持不变。
- 已安装源 skill、仓库镜像与 Python 执行逻辑一致，相关验证全部通过。
- 提交中不包含聊天内容、候选人资料、本地状态、Cookie、凭据或登录数据。
