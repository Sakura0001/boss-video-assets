# AI 主动打招呼固定话术更新设计

## 目标

将主动打招呼成功后发送的三条知识库消息替换为用户批准的 AI 应用研发话术。三条消息必须作为纯文本按固定顺序原样发送，不包含 Markdown 星号，也不得由模型改写或扩写。

## 固定消息

第一条：

```text
我们团队正在探索AI时代下一代智能应用形态，围绕大语言模型（LLM）、AI Agent、RAG、知识增强、智能工作流、多Agent协同等技术方向，打造能够理解任务、主动分析、自动执行的企业级智能应用，让AI真正进入实际业务场景。
```

第二条：

```text
目前AI Agent方向处于快速发展阶段，团队持续投入前沿技术探索和产品落地，覆盖智能助手、自动化决策、智能分析、企业知识管理、AIOps等多个场景。加入团队后可以深入参与从模型应用设计、Agent架构搭建到生产系统落地的完整流程，积累AI时代核心技术能力。
```

第三条：

```text
我看了一下你的背景，和我们AI应用研发方向有一定匹配度。如果方便的话，辛苦发我一份附件简历，我可以进一步帮你评估岗位匹配情况，也欢迎你了解一下我们的技术方向和发展机会。我们这边相对wlb一些，自盈利部门，年终奖可以保证，日常加班可以随意申报，也不会强制要求来。部门整体氛围好，新老员工无断层现象，跳槽到外面的员工都有很大幅度的涨薪，不需要担心个人竞争力。
```

第三条中的奖金、加班和职业发展描述是用户明确批准的固定主动话术。该批准只覆盖整条消息的原样发送，不授权模型在候选人追问时编造奖金金额、作息细节、录用结果或进一步承诺。

## 数据来源与运行方式

- 已安装的 `boss-zhaopin` skill 仍是唯一业务来源。
- 在源 skill 的 `references/greetings.md` 中保留现有三个固定标题，每个标题下保存一条单行、反引号包裹的纯文本消息。
- `scripts/greet_only.py` 继续在启动时从仓库镜像读取三条消息，并交给 `boss send-sequence` 逐条发送和精确读回验证。
- Python 执行器和 Boss CLI 无需修改；本次仅更新知识库、规则一致性说明和测试。

## 规则一致性

- 更新 `references/recruiter_voice.md` 的固定开场，并把“禁止提 AI、Agent”收窄为“禁止暴露由 AI、Agent、自动化或知识库代为处理”；批准话术中的技术方向名词可以发送。
- 在 `references/risk_policy.yaml` 中登记这三条为批准的固定主动岗位介绍，同时明确不得扩写。
- 在薪资和作息 FAQ 中注明：第三条固定话术可以原样主动发送；候选人继续追问具体奖金金额、作息或其他待遇时，仍使用现有保守 FAQ，不自行补充未知细节。
- 数据库岗位资料和一般候选人回复口径保持不变，避免把整个招聘知识库误改成单一 AI 岗位。

## 测试与同步

1. 先更新源 skill 的契约测试，使其精确校验三条新消息、顺序和纯文本形式。
2. 先运行测试并确认旧话术断言会失败，再更新知识库和一致性规则使测试通过。
3. 运行源 skill 的运行时测试、契约测试、同步测试和 skill 校验。
4. 使用官方同步脚本覆盖仓库的 `skills/boss-zhaopin/` 镜像。
5. 在仓库中再次运行镜像测试、顶层 `greet_only` 测试和 `--validate-only`。
6. 仅提交本次相关文件并推送当前分支；不启动 Boss、不发送真实招呼。

## 成功标准

- Python 校验得到恰好三条消息，内容与本设计逐字一致且不含 `**`。
- 源 skill 与仓库镜像完全一致。
- 相关测试与静态校验全部通过。
- Git 提交和远端分支包含本次变更，不包含本地状态、聊天或候选人隐私数据。
