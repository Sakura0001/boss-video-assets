# 主动招呼第三段话术与后续状态调整设计

## 目标

把主动招呼的第三段固定纯文本替换为用户批准的新文案，并取消该段之后的附件简历请求动作。新流程以候选人的在线简历为依据，引导已投递候选人评估是否转投。

## 固定文案

第三段必须逐字发送以下纯文本，不使用 Markdown，不拆分，不扩写：

`我看了一下你的背景和在线简历，和我们AI应用研发方向有一定匹配度。欢迎你了解一下我们的技术方向和发展机会。我们这边相对wlb一些，自盈利部门，年终奖可以保证，日常加班可以随意申报，也不会强制要求来。部门整体氛围好，新老员工无断层现象，跳槽到外面的员工都有很大幅度的涨薪，不需要担心个人竞争力。如果你现在已投递的话，也开始对比下现在投递的部门，看是否想转投，现在还可以转，后面正式进流程就没办法在转投了`

保留用户原文中的“在转投”写法，不自行润色。

## 流程变化

1. Boss 平台默认招呼成功后，仍在同一个精确会话中依次发送三段固定纯文本。
2. 第三段发送并读回验证成功后，不执行 `request-attachment-resume`，也不使用 `--request-resume`。
3. 候选人状态从 `greeted` 更新为 `waiting_application_status`，不再更新为 `waiting_resume`。
4. 候选人后续主动发送附件简历时，现有附件接收、验证和评估流程继续有效。
5. 历史候选人状态和运行数据库不迁移、不重写。

## 业务来源与代码范围

- 先更新已安装源技能中的固定话术、主动招呼步骤、状态机和语气说明。
- 更新 Python 执行器的第三段知识库标题及成功后的状态写入。
- 更新执行器测试，锁定新文案、三段发送顺序、无附件请求参数和新状态。
- 通过源技能同步脚本生成仓库 `skills/boss-zhaopin/` 镜像，不直接维护镜像。

## 错误处理与安全边界

- 三段中的任意一段发送或验证失败时，保持现有立即停止规则，不继续状态流转。
- 不增加额外消息，不处理未读聊天，不启动主动招呼任务。
- 不修改求职期望黑名单、学校、学历、毕业年份、专业和去重规则。

## 验证标准

- 知识库读取结果与用户新文案逐字一致，且三条均为纯文本。
- 执行器只调用一次三消息序列，不携带附件简历请求行为。
- 三条消息验证成功后写入 `waiting_application_status`。
- 源技能运行时测试、技能契约测试和快速校验全部通过。
- 同步后的仓库镜像与源技能一致，仓库测试通过。
