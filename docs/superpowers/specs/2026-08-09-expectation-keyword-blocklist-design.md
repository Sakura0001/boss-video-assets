# 推荐牛人期望关键词拦截设计

## 目标

在主动打招呼的资格判断中增加“求职期望”黑名单。候选人的 `expect` 字段只要出现“算法、通信、硬件、前端、unity、电气”任一关键词，就不得打招呼，也不得发送后续三条固定消息。

## 匹配规则

- 关键词直接硬编码在 `scripts/greet_only.py`，不新增运行参数或配置项。
- 匹配前移除空白并转换为小写，因此 `Unity`、`UNITY`、`unity3D` 都命中 `unity`。
- 中文按子串匹配。例如“算法工程师”“电子/通信（行业）”“电气工程师”分别命中“算法”“通信”“电气”。
- `expect` 为空或未命中黑名单时，继续执行现有毕业年份、学历、学校、专业和去重规则，不额外放宽或收紧其他门槛。
- 命中黑名单时返回内部原因 `expectation_blocked`，不得向候选人解释筛选原因。

## 实现范围

- 在 `scripts/greet_only.py` 定义固定关键词元组，并在 `EligibilityPolicy.evaluate()` 的最前面检查 `candidate.expect`。
- 保持 Boss CLI 的推荐字段采集不变；CLI 已能把 `expect` 放入 JSON，Python 已能读取该字段。
- 更新已安装 `boss-zhaopin` skill 的资格门槛和主动打招呼说明，再通过同步脚本更新仓库镜像。规则文档明确列出同一组硬编码关键词，但 Python 不从文档动态解析。
- 不把求职期望写入本地状态库，不记录候选人的完整期望文本。

## 测试

1. 将通用合格候选人测试夹具的默认期望改为不受限的“上海 后端开发”。
2. 参数化验证六个关键词均返回 `expectation_blocked`，并覆盖 `Unity` 大小写形式。
3. 验证未命中关键词的候选人仍按原规则通过。
4. 在执行器测试中放置一个命中黑名单的候选人和一个正常候选人，确认前者不会触发 `boss greet`，后者可继续被处理。
5. 更新 skill 契约测试，确认规则说明包含六个固定关键词。
6. 运行顶层 Python 测试、源 skill 测试、镜像同步检查、skill 校验和 `--validate-only`；不执行真实 Boss 招呼。

## 成功标准

- 任一黑名单关键词出现在 `expect` 中时，候选人不会进入打招呼动作。
- 未命中者的原有筛选结果不变。
- 源 skill 与仓库镜像一致，所有相关测试通过。
- 变更不包含聊天内容、候选人资料、本地状态或登录数据。
