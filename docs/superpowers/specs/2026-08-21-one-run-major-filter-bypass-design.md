# 单次主动招呼忽略专业筛选设计

## 目标

为主动打招呼执行器增加一个显式、非持久化的单次运行开关，使本次招呼不以专业字段作为资格门槛。专业字段无论已识别、未识别、为空或缺失，都可以继续通过其余资格判断。

默认行为必须保持不变：未提供开关时，候选人当前学历对应的专业仍须命中批准专业或其确定性别名。

## 已批准方案

采用命令行布尔参数 `--skip-major-filter`。该参数只作用于当前 Python 进程，不写入配置或本地状态，也不改变以后运行的默认值。

没有采用全局修改专业规则的方案，因为它会污染未来运行；没有采用 `default|any-major` 配置档，因为本次只有一个布尔例外，引入配置档会增加不必要的复杂度。

## 适用范围

- 仅影响 `scripts/greet_only.py` 发起的新候选人推荐与主动招呼。
- 不改变未读聊天、已有会话自动回复、简历评估或候选人转化流程的专业门槛。
- 不改变 Boss 当前默认岗位；未指定 `--job` 时仍使用推荐页当前选中的岗位。
- 不改变三条固定纯文本话术。

## 资格判断顺序与语义

资格判断继续按以下顺序执行：

1. 求职期望：移除全部空白并转为小写，命中固定九词 `算法`、`通信`、`硬件`、`前端`、`unity`、`电气`、`数据`、`产品`、`分析` 中任一项时，返回 `expectation_blocked`。
2. 毕业年份：必须为 2027 届。
3. 学历：必须能识别为本科、研究生、硕士或博士。
4. 学校：可见教育经历中至少一所学校须符合目标学校及其批准别名规则。
5. 专业：
   - 默认模式下，当前学历对应专业必须命中批准专业或确定性别名，否则返回 `major_unknown_or_ineligible`。
   - `--skip-major-filter` 模式下，专业不再造成拒绝。能识别时仍保留规范专业名；无法识别、为空或缺失时使用空字符串，不保存原始专业文本。
6. 长期去重：候选人已存在于长期去重索引时不得再次打招呼。

开关不得绕过求职期望、毕业年份、学历、学校或去重门槛。

## 架构与数据流

1. `build_parser()` 新增 `--skip-major-filter`，默认值为 `False`。
2. `main()` 将开关转换为清晰的执行器配置，例如 `require_major = not args.skip_major_filter`。
3. `CampaignRunner` 保存本次运行的专业筛选模式，并在每次候选人资格判断时显式传给 `EligibilityPolicy.evaluate()`。
4. `EligibilityPolicy.evaluate()` 始终先执行期望、年份、学历和学校门槛，然后尝试解析当前学历的规范专业；只有默认模式会因解析失败而拒绝。
5. `--validate-only` 输出 `majorFilterMode`，值为 `required` 或 `skipped`，以便实跑前审计本次模式。
6. `job-selected` 运行事件也输出同一模式，确保日志能够证明本次例外已显式启用。

该设计不新增第二套推荐脚本，也不把单次例外写入 skill 配置，从而避免入口分叉和残留状态。

## 状态与隐私

- 已识别专业继续按规范名写入现有本地运行状态。
- 放宽模式下无法识别的专业以空字符串写入，不保存候选人的原始专业文本。
- 不把求职期望全文、候选人资料、聊天内容、Cookie、凭据或本地状态提交到 Git。
- 运行结束、中断或失败后，下一次未携带参数的执行自动恢复默认专业门槛。

## 错误处理与运行安全

- 目标数量仍限制为每天最多 150 个，候选人检查上限仍为 1500。
- 继续逐个候选人执行，不使用 shell 循环或并行发送。
- 继续限制在 Asia/Shanghai 09:00–21:00 时段。
- 验证码、风控、投诉、明确停止联系、岗位中途变化或任何已确认状态修改失败时立即停止。
- `boss greet` 仅在无法确认按钮状态时跳过该候选人；其他 greet、chat 或 send 失败不继续下一步。
- 进程锁、Ctrl+C 安全退出、长期去重和每日计数逻辑保持不变。

## 测试设计

先写失败测试，再实现功能：

1. 默认模式继续拒绝未知专业、空专业及缺失专业，原因保持为 `major_unknown_or_ineligible`。
2. 放宽模式允许未知专业、空专业及缺失专业；可识别专业仍返回规范专业名，无法识别时返回空字符串。
3. 放宽模式仍拒绝九项求职期望黑名单、非 2027 届、缺失或不合格学历、非目标学校。
4. 执行器在放宽模式下仍执行长期去重，且不会向已去重候选人发送任何消息。
5. 参数解析默认关闭、显式参数开启；`--validate-only` 分别输出 `required` 与 `skipped`。
6. 运行事件包含专业筛选模式，方便审计。
7. 更新已安装 `boss-zhaopin` 源 skill 的规则和契约测试，明确该开关仅适用于单次主动招呼；随后通过同步脚本更新仓库镜像。
8. 运行源 skill 测试、镜像一致性测试、顶层 Python 测试、skill 校验以及两种模式的 `--validate-only`。

## 实跑流程

实现、验证、提交并推送后，使用当前登录账号对应的独立状态目录执行：

```bash
python3 scripts/greet_only.py --skip-major-filter --target 150 --max-scans 1500
```

实跑前先按 skill 要求初始化并清理过期状态、检查当日计数、验证 Boss 登录及参数模式。运行期间持续核对已确认招呼数；达到 150 后验证当日去重记录和 `waiting_resume` 状态。若平台权益上限、验证码或风控先出现，则以本地已确认记录为准立即停止并报告实际完成数。

## 成功标准

- 本次显式启用开关后，专业为空、缺失或无法识别的候选人可通过专业步骤。
- 求职期望九词、2027 届、学历、学校、去重、时段、150 上限和风控规则仍全部生效。
- 默认运行和未读/后续回复流程继续要求专业匹配。
- 验证输出与运行事件明确记录本次专业筛选模式。
- 源 skill、仓库镜像和 Python 行为一致，相关测试全部通过。
- 实跑完成 150 个已确认招呼，或在平台限制/风控出现时安全停止并报告可验证的实际数量。
